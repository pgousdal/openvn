# M6 — Native Amiga Runtime Completion

## Current state

M6 is **INCOMPLETE**. The canonical native-planar graphics and story execution
path and the full automated release gate are verified. Native MOD/Paula output
is now demonstrated; the sole remaining blocker is the final explicit human
quality and post-choice listening acceptance.

The compiler emits OpenVN Story Format 0.3/0.4 and generates static C story and
asset tables for the native runtime. The portable story engine implements text,
choices, jumps, typed deterministic variables and conditional branches. The
Amiga package pipeline converts classic graphics to shared-palette ILBM,
characters to masked planar artwork, WAV effects to 8SVX, and retains MOD music.

The native runtime has Intuition display/window management, double buffering,
DataTypes and classic ILBM loading paths, native bitmap blitting, bitmap-font
dialogue/choice rendering, input handling, and timer.device-driven four-channel
Paula MOD playback. `examples/demo` is the canonical end-to-end fixture.

Repository audit on 2026-08-10 found that release verification allowed four
contract failures: DataTypes disposal, DataTypes rendering, native bitmap
allocation and signal-driven MOD integration. Their production paths were
restored and the allowlist was removed. No xfail or unconditional skip markers
exist. Two Python test modules conditionally skip native host-build tests only
when no working C compiler is present; release verification instead requires the
compiler, CMake and CTest and does not accept those skips as success.

## Definition of done

M6 is complete only when a packaged, small OpenVN story runs in the native Amiga
player with:

- background and masked character graphics;
- multiple dialogue lines and interactive choices;
- deterministic typed variables and conditional branching;
- labels/jumps and at least two reachable endings;
- real MOD playback that continues while waiting for input;
- zero known, accepted, hidden or allowlisted release-test failures; and
- the complete release verification suite passing, including an m68k Amiga
  executable-format check.

## Acceptance record

The canonical `examples/demo` package was built as a real m68k Amiga Hunk
executable and exercised under FS-UAE 3.2.35. Human target validation confirmed:

- both `ENDING: A New Story` and `ENDING: The Last Note`;
- background and masked character rendering, including transparency;
- readable dialogue, choice rendering and responsive choice input;
- deterministic bool, int and string variables, conditions and jumps;
- clean runtime shutdown after both paths.

The prior audio acceptance was invalid: FS-UAE/Amiga disk-drive sounds were
mistaken for OpenVN MOD playback. The earlier non-silent emulator capture does
not demonstrate Paula output. Native MOD playback, including continuous music
while waiting for input, remains unverified.

The optional DataTypes renderer is separate from the canonical native-planar
acceptance path. Its contracts remain automated, but visual DataTypes
qualification was not a requirement of this M6 definition of done.

## Dependencies

- Python 3.11+, uv and locked Python development dependencies
- host C compiler, CMake 3.16+ and CTest
- `m68k-amigaos-gcc`, Amiga NDK headers/libraries and the configured CMake
  toolchain file
- FS-UAE plus a user-supplied legal Kickstart ROM for emulator validation

The reproducible toolchain contract, environment variables and FS-UAE checklist
are in [`amiga-development.md`](amiga-development.md).

## Risks

- Amiga SDK variants expose different inline/stub bindings for DataTypes calls.
- OCS chip-memory, bitplane alignment and blitter timing differ from host tests.
- timer.device and audio.device completion signals can interact with input and
  screen-buffer waits; music must continue while a choice is displayed.
- The RTG DataTypes path and classic ILBM path need separate native validation.
- Generated assets can pass format tests yet still expose palette or mask issues
  on a real planar display.

## Validation procedure

From the repository root:

```sh
uv sync --project compiler --all-extras
uv run --project compiler ruff format --check .
uv run --project compiler ruff check .
uv run --project compiler pytest -q
uv run --project compiler openvn validate examples/demo
uv run --project compiler openvn compile examples/demo --strict
uv run --project compiler openvn build examples/demo --clean
cmake -S runtimes/amiga-native -B build/host
cmake --build build/host --parallel
ctest --test-dir build/host --output-on-failure
./scripts/release-check.sh
git diff --check
```

Then launch the generated FS-UAE configuration, traverse both choices, and
record the emulator/AmigaOS configuration used. `release-check.sh` is the
automated gate: it must exit nonzero for any Python, host-runtime, m68k build or
executable-format failure.

## Native graphics follow-up — 2026-08-11

The black-screen investigation found that the first failure preceded the
renderer: libnix automatically opened `datatypes.library` because the optional
backend used the conventional `DataTypesBase` symbol. The library failed before
`main` on the tested Kickstart 3.1 system. OpenVN now uses a neutral library-base
symbol and opens DataTypes explicitly only when that backend is selected.

Target rendering then exposed three classic-screen bugs: drawing began before
the old screen buffer was safe, an off-screen bitmap was attached to the
window's layered RastPort, and the fullscreen fast path assumed Intuition-owned
screen-buffer planes were contiguous. The runtime now waits for buffer ownership
before drawing, uses a dedicated layerless RastPort for the backbuffer, and uses
`BltBitMapRastPort` for layout-safe background copies. Text uses palette pens 1
and 2; the former pen 31 is black in the canonical background palette.

FS-UAE 3.2.35 was tested with the legal local Kickstart 3.1 ROM revision 40.63
and a legal Kickstart-3.1-compatible Amiga development system. The launcher now
copies the generated minimal Startup-Sequence into its temporary OS volume and
runs the required `SetPatch` initialization instead of executing unrelated
machine-specific startup extensions.

## Native audio follow-up — 2026-08-11

The invalid disk-noise result led to four concrete findings in the production
path:

- audio.device waveform buffers came from ordinary `malloc` memory rather than
  word-aligned, custom-chip-accessible memory;
- `CMD_WRITE` used `SendIO`, which clears audio.device's special flags, instead
  of `BeginIO` with `ADIOF_PERVOL`;
- the first pattern row was inspected before the MOD player decoded it; and
- the demo's click effect stopped the MOD player and timer immediately before
  the interactive choice.

The backend now copies MOD and 8SVX samples to `MEMF_CHIP | MEMF_PUBLIC`, uses
the documented audio.device request lifecycle, decodes a row before triggering
its voices, and lets a sound effect temporarily use channel 0 without stopping
the sequencer or the other music channels. Bounded target logging records device
open results, module recognition, the first 32 ticks and the first 32 voice
programming operations.

The former canonical module contained only one four-byte sample impulse and one
note, so it could not provide a meaningful music acceptance signal. It has been
replaced by a deterministic repository-owned ProTracker fixture with a 64-byte
looped waveform and an eight-note repeating melody; the generator is
`scripts/generate-demo-mod.py`.

FS-UAE 3.2.35 was run from directory-backed hard drives with zero floppy drives,
floppy volumes set to zero, and `uae_sound_output=exact`. The target log confirms
all four audio.device channels opened, the MOD was recognized, its sample was
copied to Chip RAM, notes were programmed at volume 64 and periods 428, 339,
285 and 214, and row/tick progression continued through repeated melody cycles
while the choice waited. A separate 12-second, 48 kHz stereo PipeWire capture
contained sustained waveform output. A human listener confirmed that actual
music—not drive noise—was audible.

The final quality and post-choice listening observations must still be recorded
explicitly before M6 is marked complete.
